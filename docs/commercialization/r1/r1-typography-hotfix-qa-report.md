# R1 typography and React-warning hotfix — local QA

Date: 2026-10-20. Branch: `Per-PEDS`. Baseline HEAD: `115fc0a`. Target: branch push for review only; no deployment.

## Change and observed defect

Risk: MEDIUM (responsive UI typography); the 320px standings overflow also touched local layout. The home poster combined two already-punctuated translated sentences with `·`, and its Playfair 900/tight spacing crowded Vietnamese uppercase accents. The Engineering and Championship headings showed the same crowding in baseline screenshots. At 320px, the standings category control overflowed in English and a long driver surname clipped. React 18.3.1 emitted the `fetchPriority` DOM-prop warning in development mode.

The home poster now renders two controlled lines with no added separator. VI headlines use Inter/system sans at weight 700 with normal tracking and safer line height; EN headlines retain the Playfair treatment at supported weight 700. Engineering and Championship VI headings receive the same targeted treatment. The 320px standings control wraps within its container, and long driver names shrink/wrap rather than clip. The hero image keeps the native lowercase `fetchpriority="high"` attribute; the secondary gallery image no longer redundantly requests high priority.

## Visual and machine-readable evidence

Before/after screenshots were inspected locally at 320, 375, 390, 768, 1024 and 1440px. The confirmed poster punctuation/accent collision, Engineering/Championship accent crowding, 320px driver-name clipping and desktop article-title orphan were corrected. Per the owner's request, temporary PNG captures were removed before branch push; no screenshot is included in this commit. The reproducible capture script remains available.

Retained logs: [64-case typography results](typography-evidence/push-review-results.json), [development-mode warning check](typography-evidence/final-dev-results.json), [responsive regression](typography-evidence/responsive/browser-results.json) and [Intro lifecycle](typography-evidence/intro/intro-lifecycle-results.json). Screenshots were inspected after `document.fonts.ready`. The `remote` test mode attempted Google Fonts, but no remote font faces loaded in Chrome in this environment. `fallback` mode explicitly blocked Google Fonts. Therefore successful-Google-Font rendering is **NOT TESTED**, not PASS. A separate HTTP HEAD to Google Fonts returned 200; this does not establish successful Chrome font rendering.
